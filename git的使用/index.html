本篇只是我在公司中真正实操的git操作，后面用到什么补什么….

就不说什么概念了 都有ai。。。

  1. 老三套：
    git add : 就是将文件放到暂存区 git add . 命令将所有修改的文件暂存上去
    git commit : 前司严格要求-m‘’中的提交格式 现在想确实有必要 格式一致绝对增加了分支任务的可读性
    git push : 将我的提交“推”到远程仓库（github…）上 没啥说的
  2. 关于git pull：
    在公司的一路摸爬滚打中，我深刻领悟到了pull的必要性，所以一般在进行开发时，我会先问别人的分支是不是弄完了，他弄完了我在pull，这样减轻冲突的概率（不一定），假如说他没干完，笑死，那就解决冲突
  3. 关于冲突的解决：
    首先得明白冲突的原理：我和他开了俩分支，并且修改了同一个文件，我先把自己的分支merge上去的时候，他还没干完，当他要merge的时候就会有冲突（笑死）。
    ps：我一般解决冲突的话会放到合并解析器中 有时候需要协调一下看看留他的还是我的
  4. 关于本地 远程仓库的建立：
    在上线项目代码fork到自己账号的仓库下，在本地IDE clone你的fork项目仓库地址 （这有个问题之后解决下 我克隆下来的本地仓库会不会自动和fork的仓库建立连接 mentor说可以 我的电脑不行 有待求证 今晚没时间了。。。）
    但是说如果没有建立连接的话 你push的时候就会报错 跟着那个报错的命令 就建立了连接
    那么建立连接之后 你本地push的话就会更新fork的仓库 然后将fork的仓库创建pr到主项目 等待审核 （我的建议是找准分支 目前我遇到的是在dev分支上也就是开发分支上进行操作 克隆和pr都要找对分支）
  5. git branch :
    查看当前分支
    git branch 分支名 创建分支
    git branch -vv 可以查看当前分支与哪个远程分支建立了联系
  6. git checkout -b 分支名 ：
    创建分支并且切换到这个分支
  7. git cherry pick :
    这个命令我mentor说非常好用 我还没具体实操过 用了再补。。。
